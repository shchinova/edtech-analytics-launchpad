## Описание отчётов

### R1 — Финансовый дашборд

**Получатель:** CEO, финансовый директор  
**Периодичность:** обновляется ежедневно, просматривается по необходимости  
**Формат:** интерактивный дашборд в Tableau Public  
**Где смотреть:** ссылка на дашборд в корпоративном Notion / README проекта  
**Кто отвечает:** аналитик данных (настройка), обновляется автоматически

**Состав:**
- Выручка за текущий месяц vs прошлый месяц (динамика MoM%)
- MRR по подпискам
- ARPU и средний чек
- Выручка по типам курсов (курс / интенсив / подписка)
- Выручка по предметам топ-5
- Кумулятивная выручка с начала года

### R2 — Еженедельный отчёт по выручке

**Получатель:** CEO, финансовый директор  
**Периодичность:** каждый понедельник за прошедшую неделю  
**Формат:** короткий текстовый отчёт (1 страница) + таблица  
**Где смотреть:** отправляется в Telegram или на email  
**Кто отвечает:** аналитик данных

**Состав:**
- Выручка за неделю и сравнение с предыдущей неделей
- Количество новых платящих пользователей
- Топ-3 курса по выручке за неделю
- Флаги аномалий (если выручка упала более чем на 20%)

### R3 — Маркетинговый дашборд

**Получатель:** маркетолог  
**Периодичность:** обновляется ежедневно  
**Формат:** интерактивный дашборд в Tableau Public  
**Где смотреть:** ссылка в корпоративном Notion  
**Кто отвечает:** аналитик данных (настройка)

**Состав:**
- Расходы по каналам с динамикой
- CTR, CPC, CPM по каналам
- CAC по каналам (сколько стоит один платящий студент)
- ROAS по каналам
- Регистрации по каналам за период

### R4 — Ежемесячный отчёт по каналам привлечения

**Получатель:** маркетолог, CEO  
**Периодичность:** 1-го числа каждого месяца за прошедший месяц  
**Формат:** PDF или Google Docs с таблицами и выводами  
**Где смотреть:** отправляется в Telegram или на email  
**Кто отвечает:** маркетолог при поддержке аналитика

**Состав:**
- Сводная таблица по каналам: расходы, регистрации, платящие, CAC, ROAS
- Выводы: какой канал эффективнее, где перерасход
- Рекомендации по бюджету на следующий месяц

### R5 — Продуктовый дашборд

**Получатель:** продакт-менеджер  
**Периодичность:** обновляется ежедневно  
**Формат:** интерактивный дашборд в Tableau Public  
**Где смотреть:** ссылка в корпоративном Notion  
**Кто отвечает:** аналитик данных (настройка)

**Состав:**
- Активные пользователи (DAU / WAU / MAU)
- Completion Rate по предметам и уровням
- Средний прогресс активных студентов
- Drop-off на шаге оплаты

### R6 — Ежемесячный когортный отчёт

**Получатель:** продакт-менеджер, CEO  
**Периодичность:** 1-го числа каждого месяца  
**Формат:** PDF с тепловой картой retention  
**Где смотреть:** отправляется в Telegram или на email  
**Кто отвечает:** аналитик данных

**Состав:**
- Когортная матрица retention по месяцам (M0–M6)
- Сравнение retention между когортами
- Выводы: как меняется удержание

### R7 — Воронка конверсии

**Получатель:** продакт-менеджер, маркетолог  
**Периодичность:** еженедельно  
**Формат:** дашборд + еженедельный снимок в Slack/Telegram  
**Где смотреть:** дашборд в Tableau Public  
**Кто отвечает:** аналитик данных

**Состав:**
- Воронка: регистрации → записи → оплаты → завершения
- CVR на каждом шаге
- Динамика воронки по неделям

### R8 — Выгрузка активных студентов

**Получатель:** куратор учебного процесса  
**Периодичность:** каждый понедельник  
**Формат:** Excel-файл  
**Где смотреть:** отправляется на email куратора  
**Кто отвечает:** аналитик данных (или автоматический скрипт)

**Состав:**
- user_id, имя (если есть), email
- Курс, прогресс, статус
- Дата последней активности
- Флаг: студент не открывал курс более 7 дней

### R9 — Отчёт по качеству данных

**Получатель:** аналитик данных  
**Периодичность:** после каждого обновления данных (в идеале — ежедневно)  
**Формат:** Markdown-файл в папке reports/  
**Где смотреть:** репозиторий проекта  
**Кто отвечает:** скрипт check_quality.py (автоматически)

**Состав:**
- Количество аномалий по таблицам
- Сравнение с предыдущим запуском
- Флаги CRITICAL, требующие немедленного внимания

## Доступы

| Отчёт | Кто имеет доступ | Как получить доступ |
|---|---|---|
| R1, R3, R5, R7 (дашборды) | Все сотрудники | Ссылка в Notion, без авторизации (Tableau Public) |
| R2, R4, R6 (PDF-отчёты) | CEO, финдир, маркетолог, продакт | Рассылка в Telegram / email |
| R8 (выгрузка) | Куратор | Рассылка на email |
| R9 (качество данных) | Аналитик | Репозиторий проекта |
| Витрины в DuckDB (SQL) | Аналитик | Файл platform.duckdb |

## Что делать если отчёт не обновился

1. Проверить, запускался ли `init_db.py` сегодня
2. Проверить `reports/quality_raw.md` — нет ли CRITICAL-ошибок
3. Если всё ок — перезапустить `export_marts.py` и переподключить Tableau
4. Если ошибки есть — сообщить аналитику
