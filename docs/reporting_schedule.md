**Версия:** 2.0  
**Область:** операционный блок — привлечение, конверсия, выручка, активность студентов.  
**За рамками документа:** HR-аналитика, финансовая отчётность (P&L, бюджет), аналитика поддержки и кураторства в полном объёме.

## Инструменты доставки

| Формат | Инструмент |
|---|---|
| Дашборды (ежедневный мониторинг) | Tableau / DataLens — ссылка в корпоративном пространстве |
| Регулярные отчёты (PDF) | Корпоративная почта |
| Операционные выгрузки (Excel) | Корпоративная почта |
| Алерты при аномалиях данных | Email или Telegram-бот |
| Документация и инструкции | Confluence / внутренний портал |

## Доступы

Доступ к дашбордам разграничивается по ролям на уровне BI-платформы. Регулярные отчёты рассылаются только указанным получателям.

| Уровень доступа | Кто | Что видит |
|---|---|---|
| Полный | Аналитик данных | Все слои DWH, все дашборды |
| Управленческий | CEO, CFO | Финансовые дашборды, сводные отчёты |
| Операционный | Продакт, маркетолог, руководитель учебного блока | Профильные дашборды |
| Ограниченный | Кураторы | Только выгрузки по студентам |

## Описание отчётов

### R1 — Финансовый дашборд

**Получатель:** CEO, финансовый директор  
**Периодичность:** обновляется ежедневно  
**Формат:** интерактивный дашборд в BI-платформе  
**Кто отвечает:** аналитик данных (настройка и поддержка)

**Состав:**
- Выручка за текущий месяц и сравнение с планом и прошлым месяцем
- MRR по подпискам
- ARPU и средний чек
- Выручка по типам продуктов (курс / интенсив / подписка)
- Выручка по топ-5 предметам
- Кумулятивная выручка с начала года

### R2 — Еженедельный дайджест выручки

**Получатель:** CEO, финансовый директор  
**Периодичность:** каждый понедельник за прошедшую неделю  
**Формат:** PDF на корпоративную почту  
**Кто отвечает:** аналитик данных

**Состав:**
- Выручка за неделю и сравнение с предыдущей неделей
- Количество новых платящих студентов
- Топ-3 продукта по выручке
- Флаги аномалий (выручка упала более чем на 20%)

### R3 — Ежемесячный финансовый отчёт

**Получатель:** CEO, финансовый директор, CFO  
**Периодичность:** 1-го числа каждого месяца за прошедший месяц  
**Формат:** PDF на корпоративную почту  
**Кто отвечает:** аналитик данных совместно с финансовым директором

**Состав:**
- Итоги месяца: выручка, MRR, ARPU
- Динамика ключевых метрик за последние 6 месяцев
- Структура выручки по продуктам и предметам
- Выводы и отклонения от плана

### R4 — Маркетинговый дашборд

**Получатель:** руководитель маркетинга, маркетологи  
**Периодичность:** обновляется ежедневно  
**Формат:** интерактивный дашборд в BI-платформе  
**Кто отвечает:** аналитик данных (настройка и поддержка)

**Состав:**
- Расходы по каналам с динамикой
- CTR, CPC, CPM по каналам
- CAC по каналам
- ROAS по каналам
- Регистрации по каналам за период

### R5 — Еженедельный отчёт по каналам

**Получатель:** маркетолог, руководитель маркетинга  
**Периодичность:** каждый понедельник  
**Формат:** PDF на корпоративную почту  
**Кто отвечает:** маркетолог при поддержке аналитика

**Состав:**
- Расходы и результаты по каждому каналу за неделю
- Сравнение с предыдущей неделей
- Флаги: канал с резким ростом CAC или падением регистраций

### R6 — Ежемесячный отчёт по привлечению

**Получатель:** руководитель маркетинга, CEO  
**Периодичность:** 1-го числа каждого месяца  
**Формат:** PDF на корпоративную почту  
**Кто отвечает:** маркетолог при поддержке аналитика

**Состав:**
- Сводная таблица по каналам: расходы, регистрации, CAC, ROAS
- Выводы: какой канал эффективнее, где перерасход
- Рекомендации по бюджету на следующий месяц

### R7 — Продуктовый дашборд

**Получатель:** продакт-менеджер  
**Периодичность:** обновляется ежедневно  
**Формат:** интерактивный дашборд в BI-платформе  
**Кто отвечает:** аналитик данных (настройка и поддержка)

**Состав:**
- Активные студенты (DAU / WAU / MAU)
- Completion Rate по предметам и уровням
- Средний прогресс активных студентов
- Drop-off на шаге оплаты

### R8 — Воронка конверсии

**Получатель:** продакт-менеджер, руководитель маркетинга  
**Периодичность:** обновляется еженедельно  
**Формат:** интерактивный дашборд в BI-платформе  
**Кто отвечает:** аналитик данных

**Состав:**
- Воронка: регистрации → записи → оплаты → завершения
- CVR на каждом шаге
- Динамика воронки по неделям
- Сравнение когорт между собой

### R9 — Ежемесячный когортный отчёт

**Получатель:** продакт-менеджер, CEO  
**Периодичность:** 1-го числа каждого месяца  
**Формат:** PDF на корпоративную почту  
**Кто отвечает:** аналитик данных

**Состав:**
- Когортная матрица retention по месяцам M0–M6
- Сравнение retention между когортами
- Выводы: как меняется удержание, какие когорты аномальны

### R10 — Отчёт по успеваемости курсов

**Получатель:** руководитель учебного блока  
**Периодичность:** 1-го числа каждого месяца  
**Формат:** PDF на корпоративную почту  
**Кто отвечает:** аналитик данных

**Состав:**
- Completion Rate по каждому предмету и уровню
- Dropout rate: на каком проценте прогресса бросают чаще всего
- Сравнение курсов между собой по успеваемости
- Предметы с аномально низкой доходимостью

### R11 — Выгрузка активных студентов

**Получатель:** кураторы учебного процесса  
**Периодичность:** каждый понедельник  
**Формат:** Excel на корпоративную почту  
**Кто отвечает:** автоматический скрипт

**Состав:**
- ID студента, email, курс, прогресс, статус
- Дата последней активности
- Количество дней без активности

### R12 — Выгрузка студентов под риском

**Получатель:** кураторы учебного процесса  
**Периодичность:** каждый понедельник  
**Формат:** Excel на корпоративную почту  
**Кто отвечает:** автоматический скрипт

**Состав:**
- Студенты без активности более 7 дней при статусе active
- Студенты с прогрессом менее 20% и enrollment старше 30 дней
- Приоритет для куратора: чем дольше неактивен, тем выше

### R13 — Операционный дашборд

**Получатель:** руководитель операционного блока  
**Периодичность:** обновляется ежедневно  
**Формат:** интерактивный дашборд в BI-платформе  
**Кто отвечает:** аналитик данных

**Состав:**
- Регистрации и записи за сегодня / неделю / месяц
- Оплаты за день: количество и сумма
- Drop-off на оплате за последние 7 дней
- Студенты под риском: сводная цифра для быстрого контроля

### R14 — Отчёт по качеству данных

**Получатель:** аналитик данных  
**Периодичность:** после каждого обновления данных  
**Формат:** Markdown в папке reports/  
**Кто отвечает:** скрипт check_quality.py (автоматически)

**Состав:**
- Количество аномалий по таблицам и уровням критичности
- Сравнение с предыдущим запуском
- CRITICAL-флаги, требующие немедленного внимания

## Что делать если отчёт не обновился

1. Проверить, запускался ли `init_db.py` сегодня
2. Открыть `reports/quality_raw.md` — нет ли CRITICAL-ошибок
3. Если ошибок нет — пересобрать витрины и переподключить дашборд
4. Если есть CRITICAL — устранить аномалии, затем пересобрать
